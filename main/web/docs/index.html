Guides and documentation.

Everything about Structorizer Web: drawing diagrams, files and pictures, code export, the tools for AI assistants, privacy and running it yourself.

Structorizer Web is a browser version of Structorizer, the Nassi-Shneiderman diagram (NSD, structogram) editor used in many schools. It runs on Windows, macOS, Linux, Chromebooks and on the iPad in Safari, without installation and without an account.

What it does

  • All element types of Structorizer Desktop 3.32: instruction, IF, CASE, FOR, WHILE, REPEAT, endless loop, call, exit (jump), parallel section and try-catch.
  • Programs, subroutines and includable diagrams, several open at once (Arranger index).
  • Opens and saves the .nsd files of Structorizer Desktop, so teachers and pupils can switch between both.
  • Pictures as PNG, PNG (multiple), EMF, PDF and SVG, and printing.
  • A live Code preview and code export to Python, Java, JavaScript, C++, PHP and Bash.
  • Find and replace, transmute, outsource, collapse, disable, undo and redo, the desktop keyboard shortcuts.
  • German and English, light and dark mode, touch and pencil friendly.
  • Tools for AI assistants through the MCP server.

Not yet included

The Executor (running and debugging diagrams), the Turtleizer, the Analyser and source code import follow in later versions. They appear in the Debug menu as "planned". See the roadmap.

Your first diagram

  1. Open the editor. A new, empty program called ??? appears.
  2. Double-click (or double-tap) the frame and type a name, for example Temperature.
  3. Tap the empty field in the middle (the ∅ sign), then the instruction button in the toolbar (or press F5).
  4. Type INPUT "Temperature in °F: ", f and confirm with Shift+Enter or OK.
  5. The new element stays selected. Add the next one the same way: c <- (f - 32) * 5 / 9, then OUTPUT "°C: ", c.

New elements are inserted after the selected element. To insert before it, hold Shift while clicking the element button, or switch on the "insert before" button (arrow up) on a touch screen.

Examples

File › Examples contains a temperature table, a diagram with every element type and the recursive hilbert subroutine from the desktop samples.

On the iPad

Open the address in Safari and choose Share › Add to Home Screen. Tap selects, double tap edits, a long press opens the context menu, and long press plus moving drags an element to a new place. Pinch to zoom.

Screen layout

  • Menu bar with the menus of Structorizer Desktop 3.32: File, Edit, View, Diagram, Preferences, Debug, Help. On narrow screens they are collected in one Menu button.
  • Toolbar with one button per element type, then edit, delete, cut, copy, paste, move, disable and collapse, and the zoom.
  • Work area with the diagram. Right click or long press opens the context menu.
  • Side panel on the right with two tabs, Arranger index and Code preview. Open or close it with the panel button at the top right, Shift+F3 or Shift+F4. Drag its left edge to change the width.
  • Status bar showing the selection and whether the diagram is saved in the browser.

Editing elements

Double-click an element or press Enter to open the element editor: text, comment, one of the ten desktop colours and "disabled". Multi-line instructions hold one statement per line. A line ending with \ continues on the next line.

Diagram › Transmute (Ctrl+T) splits a multi-line instruction into single ones, or changes instruction ⇄ call ⇄ exit and WHILE ⇄ REPEAT. Diagram › Outsource moves the selected element into a new subroutine and replaces it with a call.

Operators

Assignment <- or := (shown as ←), comparison =, <>, <, <=, >, >=, logic and, or, not, arithmetic + - * /, div and mod. The keywords (INPUT, for, while ...) can be changed in Preferences › Parser keywords; files keep their own keywords.

Subroutines

Set the type with Diagram › Type › Sub. The header holds name and parameters in Pascal, C or BASIC style: fact(n: int): int, int fact(int n) or fact(n as Integer) as Integer. A function returns its result by assigning it to result or to its own name, or with return. The full syntax is described in the user guide, chapter 6.

Open and save

File › Open (Ctrl+O) reads .nsd files of Structorizer Desktop or Structorizer Web; several files can be chosen at once. A file opens next to the current diagram unless the current one is still empty.

File › Save (Ctrl+S) writes an .nsd file for Structorizer Desktop 3.32. Chrome and Edge can write the same file again; Safari, Firefox and the iPad download a copy into the downloads folder. Save all saves every changed open diagram.

Autosave and recent files

All open diagrams are kept in this browser automatically and come back when you open the editor again. File › Open recent file lists the last ten files you opened or saved; their contents are stored in this browser, never on a server. Preferences › Data deletes everything.

Clear and close

File › Clear diagram deletes all elements (undo brings them back). File › Close diagram closes the current diagram; the Arranger index shows the others.

Pictures always use the light colours, also in dark mode, and the view options that are switched on (comments, highlighting, C operators). Edit › Copy diagram as picture puts a PNG on the clipboard. File › Print (Ctrl+P) prints only the diagram; choose "Save as PDF" in the print dialog for a PDF.

The Code preview tab of the side panel shows the diagram as program code while you edit, like Structorizer Desktop 3.32. The code of the selected element is highlighted, and clicking a code line selects its element. Every file starts with Generated by Structorizer 3.32-35 (Web).

Languages

Python, Java, JavaScript, C++, PHP and Bash. Choose the favourite language in the panel or in Preferences › Code export; File › Export › Code offers all of them and Ctrl+Shift+X exports the favourite one.

What the export does

  • Operators, string literals, arrays ({1, 2, 3}) and the common built-in functions (sqrt, abs, random, length ...) are translated.
  • INPUT and OUTPUT become the input and output of the language (input()/print(), Scanner, prompt(), std::cin ...).
  • Java and C++ get declarations with types from the diagram; variables without a declaration get a guessed type and a TODO comment.
  • With "Involve called subroutines", subroutines called by the diagram are taken from the other open diagrams and exported in the same file.
  • Disabled elements become comments, element comments become code comments.

Like in the desktop version, the result is a starting point: check types and library calls before you compile it.

The Arranger index tab lists all open diagrams, grouped into main programs, subroutines (with their number of parameters) and includables. Click a name to edit that diagram, the × closes it. A dot marks unsaved changes.

Subroutines in the index are used by the Code preview for calls, and includable diagrams named in a diagram's include list (diagram editor) are exported at the start of the code.

  • General: language (German, English), appearance (system, light, dark), whether the diagram itself is drawn dark in dark mode, simplified toolbar, confirmation before deleting structured elements.
  • View: the switches of the View menu.
  • Code export: favourite language, involve called subroutines.
  • Parser keywords: the keywords of the current diagram (INPUT, for, to, while ...), optionally as the default for new diagrams.
  • Data: save preferences to a file, load them on another computer, reset them, or delete all data stored in this browser.

Light and dark mode

"System" follows the setting of the device. In dark mode the diagram is drawn on a dark background with lighter colours; switch this off under General if you prefer white paper. Exported pictures and prints are always light.

Structorizer Web comes with an MCP server like the Craft apps (WordCraft, GridCraft ...). An MCP client such as Claude Desktop, Claude Code or the WorkCraft chat starts it on your computer. It works headless on .nsd files in a folder you choose; nothing is sent anywhere by the server itself.

Starting it

cd main/mcp
npm install
npm run build
node dist/cli.js mcp --root "C:\Users\me\Documents\Diagrams"

Configuration for Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "structorizer": {
      "command": "node",
      "args": ["C:/xampp/htdocs/Structorizer/main/mcp/dist/cli.js", "mcp", "--root", "C:/Users/me/Documents/Diagrams"]
    }
  }
}

--root limits every file access to that folder (default: the current folder). --read-only switches off all tools that write.

The tools

ToolDoes
list-diagramslists the .nsd files under the root folder
read-diagramreads a diagram as an outline (text) and as a JSON tree with element ids
create-diagramcreates a new diagram from a JSON tree (type, name, elements)
add-elementinserts an element (with nested elements) at a position
update-elementchanges text, comment, colour or disabled state of an element
delete-element, move-elementremoves or moves an element
export-codegenerates Python, Java, JavaScript, C++, PHP or Bash
export-picturewrites SVG or EMF next to the diagram
diagram-infoheader, parameters, variables and element counts

The tools use the same code as the editor (file format, layout and code export), so a diagram written by an assistant opens unchanged in Structorizer Web and Structorizer Desktop.

  • No server: the page is a set of static files. There are no accounts, no cookies, no analytics and no external fonts or scripts.
  • The page forbids itself to contact any server (Content Security Policy connect-src 'none').
  • Diagrams, recent files and preferences are stored only in the browser's local storage on your device. Preferences › Data deletes them.
  • Files are opened from and saved to your device only.
  • The MCP server runs on your own computer and only touches the folder you give it.

Whoever hosts the files (for example a school server) sees the usual web server logs of page requests, as with any web page.

The build in main/web/dist is a folder of static files. Copy it to any web server (Apache, nginx, IIS, a Nextcloud or GitHub Pages); no PHP and no database are needed. The page works from any sub folder.

cd main/web
npm install
npm test
npm run build

Opening index.html directly from the file system does not work in every browser; use a web server, for example XAMPP: http://localhost/Structorizer/main/web/dist/.
