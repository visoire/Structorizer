# Architecture Decisions

Each decision: ID, decision, reason. Implementation agents follow these; changing one
needs a new entry ("D-xx supersedes D-yy"), not a silent edit.

| ID | Decision | Reason |
|---|---|---|
| D-01 | Web app lives in `C:\xampp\htdocs\Structorizer\main\web\`. Vite + TypeScript (strict) + React 18 + Zustand. Vitest for tests. No other runtime dependencies without a decision entry. | React/Zustand are what cheap implementation models know best. Small dependency surface for a school app. |
| D-02 | `src/core/` is framework-free TypeScript (model, nsd io, layout, executor, generators). It must not import React, the DOM (except `DOMParser` in `core/io`) or the store. | Testable with Vitest in Node, reusable for a later native wrapper. |
| D-03 | Fully client-side. No backend, no analytics, no external fonts or CDNs at runtime. Persistence: download/upload files, File System Access API where available, `localStorage` autosave of the current diagram. | GDPR / school requirement (`sourcecode/gdpr.txt`, issue #1244). |
| D-04 | Element text is `string[]` (lines), exactly like the original `StringList`. The editor shows it joined with `\n`. | 1:1 round trip with .nsd; no lossy single-string model. |
| D-05 | Structure-from-text rules are explicit model operations: `setCaseText()` resizes `branches` to `text.length - 1` (min 2), `setParallelCount()` resizes branches and writes `text[0]`. Never resize implicitly in the renderer or reader. | Original trap #4 (source-analysis section 7). |
| D-06 | Element ids: generated by `newId()` = counter + random suffix (`e_1k3f9a`). Do not use `crypto.randomUUID()`. | `randomUUID` only exists in secure contexts; the app is also opened via `http://<lan-ip>/` on school networks. |
| D-07 | Colors of **empty** branch sequences are not modelled (dropped on read, not written). | Always `ffffff` in practice; saves a wrapper type around every branch. |
| D-08 | Written .nsd files use `version="3.32-35"` and `origin="Structorizer Web <appVersion>"`. | Desktop compares version strings when reading keywords; a desktop-like version keeps it on the modern path. |
| D-09 | Native file format = .nsd (XML). No separate JSON file format. JSON is only used internally (autosave, undo snapshots). | Teachers exchange files with the desktop version. One format, no migration later. |
| D-10 | Try: the finally block is drawn only when non-empty (or when the user explicitly adds it). | Matches desktop option "show FINALLY" default behaviour, keeps diagrams compact. |
| D-11 | Includable diagram frame: rectangle with cut top-left corner. | Original detail not worth porting; needs to be distinguishable only. |
| D-12 | Rendering = SVG generated from a pure layout tree (`core/layout`). Text measured via a pluggable `measureText` function. | Crisp on iPad, exportable as SVG/PNG, testable without a browser. |
| D-13 | Undo/redo = immutable snapshots of the diagram (store keeps `past[]`, `future[]`, max 100). Every edit is one command producing a new tree (Immer `produce` or manual copy). | Same strategy as the original, simplest correct approach. |
| D-14 | Executor (phase 2): own tokenizer + Pratt parser + tree-walking evaluator in `core/lang/`. Execution as a JS generator (`function*`) that yields before each element, so step mode / delay / breakpoints are driven by the UI. **No `eval`, no `new Function`.** | BeanShell is not available; `eval` would be a security and correctness problem. Generators make stepping trivial. |
| D-15 | Code generators are written fresh on the AST from `core/lang/`, not ported from Java. Order: JavaScript, Python, then Pascal, Java, C. | Maintainers call the Java generators unmaintainable (`sourcecode/info.txt`). |
| D-16 | UI language: German and English from the start via a tiny `t(key)` dictionary (`src/i18n/de.ts`, `en.ts`). Default from `navigator.language`. | School target group in DE; strings exist in `locales/de.txt`, `en.txt` for reference. |
| D-17 | Touch first: every action reachable by tap (toolbar + context sheet), no hover-only features, hit targets ≥ 40 px, pointer events (not mouse events). | iPad is the main motivation (issue #1244). |
| D-18 | Build output `main/web/dist/`, Vite `base: './'`. Open via `http://localhost/Structorizer/main/web/dist/`. Rebuild after every change that should be visible there. | XAMPP serves htdocs statically. |

## Added and revised with version 0.1.0 (2026-11-18)

| ID | Decision | Reason |
|---|---|---|
| D-19 (revises D-01) | React **19**, Zustand 5, Vite 8, TypeScript 5.9 (not 7), Vitest 5. Exact versions pinned in `package.json`. No Immer: the ops in `core/model/ops.ts` are hand-written immutable updates. | Current stable releases on 2026-11-18; TypeScript 7 (native) skipped until the tooling around it settles. |
| D-20 | The git repository root is `C:\xampp\htdocs\Structorizer` (GitHub `visoire/Structorizer`), the app is in `main/web/`, plans in `info/`, specs in `docs/`. `sourcecode/` (desktop copy) and `info/grok.txt` are not committed. | Layout chosen by the project owner. The desktop sources are a separate GPL project with its own repository. |
| D-21 (supersedes D-11) | Includable frame: two bevelled corners (top-left, bottom-right). The include list is shown in a bevelled box above the title. | User guide 4.1: "an includable diagram has two bevelled corners". |
| D-22 | The production build sets a Content Security Policy: `default-src 'self'; script-src 'self'; connect-src 'none'; ...` (injected by a Vite plugin, not in dev mode). | Technical guarantee that no data leaves the device (GDPR). Dev mode needs HMR, so the policy is build-only. |
| D-23 | The renderer is a pure function `sceneToSvg(scene)`. The same SVG string is shown on screen (`innerHTML`, all text escaped) and used for SVG/PNG export. Selection and drop indicators are a separate overlay SVG. | Screen and export can never differ; one code path to test. |
| D-24 | `readNsd()` returns `{ diagram, warnings }` instead of only the diagram. Repairs (e.g. inconsistent CASE) are reported to the user as a notice. | Better feedback for broken files without refusing to open them. |
| D-25 | Inserting an element opens the editor at once (like the desktop). Cancelling it removes the new element without an undo entry; OK merges insert and first edit into one undo step. | Desktop behaviour; undo history stays meaningful. |
| D-27 (revises D-15) | Code export in 3.32.35-web.2 is token based (`core/lang/lexer.ts`, `analyze.ts`, `core/gen/`), not AST based, because the Phase 2 parser does not exist yet. Every generated line records the element ids it came from (Code preview highlighting). It moves onto the AST in P2-10. | Code preview was requested now; the tokenizer is reused by the parser later. |
| D-28 | Version scheme: the web version carries the desktop version it corresponds to (3.32-35); package version `3.32.35-web.N`. | Owner's request: "the web version as 3.32 like the current Structorizer". |
| D-29 | Several open diagrams: the active one lives in the top-level store fields, the others in `docs[]` (Arranger index). Undo history is per diagram. Opening never replaces a non-empty diagram. | Simple swap model, no data loss. |
| D-30 | Picture formats: PNG/SVG from the scene, PDF = one page with the picture (Flate, JPEG fallback), EMF = own vector writer ([MS-EMF] records). SWF is listed but not produced (Flash discontinued 2020). | Desktop menu parity with formats people can still open. |
| D-31 | The MCP server (`main/mcp`, `structorizer-cli mcp`) is headless and file based, like the Craft app CLIs; it bundles the editor core with esbuild and uses `@xmldom/xmldom` as DOMParser. Elements are addressed by tree paths (`1/then/0`) because runtime ids are not persisted. `--root` confines file access. No live connection to an open browser tab (the page's CSP forbids network access). | Same results as the editor, safe defaults, no server in the web app. |
| D-32 | The Structorizer User Guide PDF is shown on the docs page but not committed (`.gitignore`); it belongs to the desktop project. | Licence of the guide not clarified for redistribution. |
| D-33 | Visual design follows the Craft design tokens (GridCraft/WordCraft `theme.rs`): neutral greys, 4/8/10 px radii, popup shadow 0 4 16, 13 px UI font, rounded square active toggle buttons with soft tint + 4 px bottom accent bar. Only values and patterns are taken, no code or assets (the Craft repos are MIT/Apache, Structorizer Web is GPL; tokens are not copyrightable code). | Owner's request; consistent with the other apps of the owner. |
| D-34 | Fonts: only fonts installed on the device (system stacks or a typed font name), never downloaded. The diagram font is a live binding in `core/layout/measure.ts` (`setDiagramFont`), carried in `scene.font` to SVG/PNG/PDF/EMF. | GDPR (no font CDNs) and exports that match the screen. |
| D-35 | Two builds from one code base: multi-file (`dist`, with docs) and single file (`dist-single`, `--mode single`, inlined script whose sha256 hash is the only allowed `script-src`). | Owner's request; the single file keeps the same CSP guarantee. |
| D-36 | Release automation: `scripts/release.sh` (bash wrapper) and `scripts/package.mjs` (Node, dependency-free zip writer, checksums). The user guide PDF is left out of the packages unless `--with-guide`. | Testable on any OS with Node; licence caution (D-32). |
| D-26 | Desktop keyboard shortcuts are kept (user guide chapter 13). Keys the browser reserves (F11, F12, Ctrl+N, Ctrl+W) cannot be guaranteed; every action is also in the toolbar. | Teachers know the desktop shortcuts. |
| D-37 (supersedes D-16) | English (`en`) is the main/default UI language (`DEFAULT_PREFS.lang = 'en'`). All 13 Structorizer Desktop locales (`en`, `de`, `fr`, `nl`, `lu`, `es`, `pt-br`, `it`, `zh-cn`, `zh-tw`, `cs`, `ru`, `pl`) are supported; English is bundled eagerly and the 12 other dictionaries load lazily as separate JS chunks in `dist` (and inline in `dist-single`). | Keeps initial bundle tiny while matching desktop language coverage and guaranteeing English default. |
| D-38 | App accent is strong icon golden yellow (`#fbc700`) instead of GridCraft teal; `#print-area` lives outside `.app` with `beforeprint`/`afterprint` hooks; `beforeunload` guards `anyDirty()` across all open diagrams; MCP (`main/mcp`) follows Craft MCP conventions (`batch`, `list-commands`, `validate-diagram`, search/replace, full tool annotations, resources & prompts). | User feedback on visual identity, empty Print-PDF bug fix, unsaved-change protection, and GridCraft/WordCraft MCP parity. |
